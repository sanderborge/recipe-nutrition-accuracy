# Master's Thesis — Nutritional Quality of AI-Generated Recipes

This repository accompanies a master's thesis comparing the nutritional quality of recipes generated by six large language models (LLMs) against ground-truth values computed from the Norwegian Food Composition Table (*Matvaretabellen*) and the USDA SR Legacy database.

## Overview

The pipeline:

1. **Generates** 1,035 recipes per model (5 recipes × 207 meal types from Allrecipes.com), for six models:
   *Gemini 2.5 Flash, Gemini 2.5 Flash Lite, GPT-5.4 Mini, GPT-5.4 Nano, Grok 3 Fast, Grok 4 Fast.*
2. **Parses** each ingredient string into amount + unit + name, converting to grams via the Helsedirektoratet portion-size table.
3. **Matches** ingredients against Matvaretabellen (primary) and USDA SR Legacy (fallback) to retrieve per-100 g nutrient values.
4. **Filters** recipes by ingredient-weight coverage (≥ 90 %) and by NaN-gram-line count (< 2 ingredients with no gram conversion).
5. **Scores** each retained recipe on the FSA traffic-light system (4–12, healthier ↓) and the WHO nutritional-quality score (0–7, healthier ↑).
6. **Compares** the LLMs' self-reported (claimed) nutrition and scores against the pipeline's calculated ground truth.

## Setup

```bash
# 1. Create and activate a Python virtual environment
python -m venv env
source env/bin/activate          # macOS / Linux
# env\Scripts\activate           # Windows

# 2. Install dependencies
pip install -r requirements.txt
#    requirements.txt covers the pipeline (pandas, numpy). To run the notebooks
#    you also need: matplotlib seaborn scipy scikit-learn jupyter

# 3. (For recipe generation only) create a .env file with API keys
#    See script/generate_recipes.py for the expected variable names
echo "OPENAI_API_KEY=..." > .env
echo "GROK_API_KEY=..."   >> .env
echo "GEMINI_API_KEY=..." >> .env
```

## Running the pipeline

```bash
# For each of the six raw recipe files:
python run_pipeline.py data/gpt54_mini_recipes_raw.csv
python run_pipeline.py data/gpt54_nano_recipes_raw.csv
python run_pipeline.py data/gemini_flash_recipes_raw.csv
python run_pipeline.py data/gemini_flash_lite_recipes_raw.csv
python run_pipeline.py data/grok_fast_recipes_raw.csv
python run_pipeline.py data/grok4_fast_recipes_raw.csv
```

Each run produces:
- `data/<model>_recipes_calculated.csv` — one row per kept recipe, with calculated nutrients, FSA scores, WHO scores
- `data/<model>_recipes_debug.csv` — one row per ingredient, with match details and grams

## Regenerating the thesis tables and figures

`notebooks/thesis_outputs.ipynb` regenerates exactly the tables and figures used
in the thesis — each cell is labelled with its thesis number, in thesis order
(tables 3.1, 3.3, 3.4, 5.1–5.8 and figures 5.1–5.6). Figures are written to
`notebooks/figures/`; tables print as plain text.

```bash
cd notebooks
jupyter nbconvert --to notebook --execute --inplace \
  --ExecutePreprocessor.kernel_name=py312-local thesis_outputs.ipynb
```

Use a kernel that has `matplotlib`, `seaborn`, `scipy` and `scikit-learn`
installed (the project `env/` kernel does **not** — `py312-local` above is one
that does). Salt is converted to sodium with factor **2.5** consistently across
the pipeline and the notebooks.

`thesis_tables.ipynb` (kept) and the archived working notebooks under
`notebooks/_exploration/` (`score_comparison`, `nutrient_comparison`,
`explore_calculated_files`, `audit_portion_matcher`) contain additional,
exploratory outputs that are **not** used in the thesis. The archived notebooks'
relative paths assume the `notebooks/` directory, so they are kept for provenance
rather than for re-running — `thesis_outputs.ipynb` supersedes them.
